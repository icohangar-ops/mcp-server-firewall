mcp-server-firewall

A capability-scoped proxy between an MCP client and an upstream MCP server — the server only ever gets the powers your policy grants it.

The problem

As r/mcp put it: "MCP is a security joke." A typical MCP server runs as a local process with effectively root-equivalent access — it can read any file the user can read (~/.ssh, ~/.aws, your .env), make arbitrary network requests, and see every environment variable in its parent process, including cloud credentials and API keys it has no business touching. There is no sandbox, no permission model, and no audit trail. The firewall is the governed gateway that should have been in the middle from the start.

What it enforces

  • Tool allowlist — the client can only call tools you name. Everything else is denied, including tools the upstream server advertises.
  • Filesystem + network egress scoping — path arguments must resolve inside configured allowed roots (.. traversal is resolved before the check), and URL arguments must point at allowlisted domains.
  • Env brokering — the upstream process is spawned with only the environment variables named in the policy. Secrets not listed never reach the server.
  • Full audit log — every request and response is recorded in JSONL with the policy decision and the human-readable reason. Denied calls return a JSON-RPC error explaining exactly which rule blocked them.
